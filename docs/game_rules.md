**CONFIRMED** `n d s` means roll `n` dice with `s` sides and add the results. In native DOS each die takes a 15-bit pseudo-random sample `U`, forms `1 + floor(U × s / 32768)`, and wraps once by subtracting `s` if the result exceeds it. The native sum is zero for nonpositive dice or sides. CD `MAIN.EXE+0x426A–0x428F, +0xC286–0xC2DB`; floppy `MAIN.EXE+0x526A–0x528F, +0xFAE0–0xFB35`. The ScummVM helper uses its own bounded RNG and optional additive constant (`engines/kyra/engine/kyra_rpg.cpp:386–395`). Fixed-point products `a × b / 256` discard the remainder at each step (CD `+0x1EC10`, floppy `+0x1F646`).

## Combat

### Attack and hit test

- **CONFIRMED** Standard unarmed item entry 3 uses hit test → maximum damage → two-dice damage syscall → apply damage. The hit code from syscall `0x40` gates the following calls and is passed through to the damage calculation. Both item scripts have these calls at DATA words `0x233, 0x23F, 0x244, 0x24D` (CD `STARTUP.PAK+0x1122D, +0x11245, +0x1124F, +0x11261`; floppy `GENERAL.PAK+0xD9D34, +0xD9D4C, +0xD9D56, +0xD9D68`). In the reference, the combat button dispatches item and level event `0x400` for each filled combat slot 0–3, decreasing an auxiliary argument by 10 after each weapon. With no occupied combat slot it dispatches entry 3 through item 0. Items:290–310, GUI:1030–1058, Script:980–995,1447–1456.
- **CONFIRMED** For a character attacker, the hit factor is default modifier 0. The critical threshold is `100 − (skill level + skill modifier)`; triple the modifier for Rogue first. A monster attacker instead supplies its own hit stat 0 and its own property skill level, with critical threshold `100 − monster skill level`. CD `MAIN.EXE+0xAD4D–0xAE04`, floppy `+0xAC8E–0xAD45`. The ScummVM monster-attacker branch reads the target-indexed slot here (LoL:3455–3457).
- **CONFIRMED** The defender's evade is character default modifier 3 or monster fighting stat 3. In native CD both target types use `evade × modifier 4 / 256` before the comparison. The difficulty row is `[128, 256, 256]` for easy/normal/hard. Native floppy passes the raw evade value. Compute `evade threshold = (evade × 256) / hit factor` with the adjusted or raw value for that edition. CD `MAIN.EXE+0xAE04–0xAEB4, +0x2B86E`, floppy `+0xAD45–0xADD6`. ScummVM scales the evade value only for a monster target (LoL:3466–3482).
- **CONFIRMED** Roll `1d100` once. A roll at or above the critical threshold returns 2 and bypasses the evade comparison. Of the remaining rolls, those below the evade threshold return 0 (miss), and all others return 1. An absent target returns 0. Sentinel attacker −1 returns 1 before the monster validity check. A monster target in mode 13 or higher gives 0 for other attackers. CD `MAIN.EXE+0xAD0A–0xAD4D, +0xAE52–0xAEB9`; floppy `+0xAC4B–0xAC8E, +0xAD93–0xADDB`; LoL:3440–3484.

### Might, armour and damage

| Rule | Formula and evidence |
| --- | --- |
| Displayed character might | **CONFIRMED** Sum eight item-might categories. If the sum is nonzero, add character base might. For a zero sum use default modifier 8 instead. Multiply by default modifier 1 and divide by 256, then multiply by total might modifier and divide by 256. CD `MAIN.EXE+0x44C8E–0x44D14`, floppy `+0x4E3FE–0x4E484`; LoL:1405–1419. |
| Character armour | **CONFIRMED** Add item protection and base protection. Multiply by default modifier 2 and divide by 256. Multiply that integer result by total protection modifier and divide by 256 again. CD `MAIN.EXE+0xA8D7–0xA927, +0xA94F–0xA95E`; LoL:1439–1452. |
| Monster armour | **CONFIRMED** Multiply the monster's item protection by its protection factor (fighting stat 2) and divide by 256. The script supplies the factor as `protection percentage × 256 / 100`. CD `MAIN.EXE+0xA928–0xA95E`; LoL:1439–1452, Script:941–957. |
| One damage category | **CONFIRMED** Start with `item might × attacker factor / 256`. The factor is character default modifier 1, monster fighting stat 1, or 256 for attacker −1. Characters multiply again by total might modifier and divide by 256. Zero at either stage returns 0. CD `MAIN.EXE+0xAF63–0xAFD6`, floppy `MAIN.EXE+0xAE85–0xAEF8`; LoL:2060–2070,3635–3647. |
| Target category factor | **CONFIRMED** Multiply by the magnitude of the target's category factor, divide by 256, then restore the sign of that factor. Index bit 7 selects category 7. Native helpers treat the factor word as signed. ScummVM's literal load from a `uint16` array promotes to a nonnegative integer in this revision. CD `MAIN.EXE+0xAFD8–0xAFFF, +0x1EBED–0x1EC0F`; floppy `MAIN.EXE+0xAEFA–0xAF21, +0x1F624–0x1F645`; LoL:2068–2070,3649–3654. |
| Armour reduction | **CONFIRMED** For nonzero damage and hit code other than 2, divide `protection × 128` by pre-armour damage, cap the result above at 217, and subtract it from 256. Multiply damage by the resulting factor and divide by 256. Raise any result below 2 to 2 in that branch. For hit code 2, skip armour and turn damage 1 into 2. Zero stays zero. CD `MAIN.EXE+0xB001–0xB052`; floppy `MAIN.EXE+0xAF23–0xAF74`; LoL:3653–3658. |
| Total and dice | **CONFIRMED** Sum the terms for all eight item categories, starting at zero. The item syscall rolls `2 d sum`, so a positive sum gives damage from 2 through twice the sum. In the reference monster melee uses the same sequence. CD `MAIN.EXE+0xB053–0xB0B4`, floppy `+0xAF75–0xAFD6`; LoL:3487–3497, Script:1447–1456, Sprites:1291–1304. |
| Applying damage | **CONFIRMED** Subtract positive damage from HP. Monster HP is clipped between zero and base HP, with death mode 13 at zero. Zero or negative damage uses a healing branch with a one-point floor. A monster already in mode 13 or higher, or an inactive or dead character, takes nothing and the routine returns 0. Party HP goes through the setter, which clips to zero and the current maximum and sets dead flag 8 below 1. Damage with flag value 4 is divided by four (shift right 2) for a target wearing item 229 (Cloud Ring). CD `MAIN.EXE+0xB0B5–0xB2DF, +0xE10D–0xE1BC`; floppy `+0xAFD7–0xB1FC, +0x1188A–0x11939`; LoL:1465–1483,3500–3588. |

### Monster attack and defense types

**CONFIRMED** Both specials are switches on a type byte of the monster definition. The type minus one is compared unsigned with the arm count (`cmp bx, 9` for attack, `cmp bx, 5` for defense); anything else, including type 0, jumps to the epilogue and does nothing. The arm is then taken from a word jump table in the code segment (CD segment base `0x10EC0`, tables at `0x11BD6` and `0x11DD2`; floppy base `0x15960`, tables at `0x165E4` and `0x1678B`). Before the switch each special rolls `1d100` and stops when the roll is above its chance byte, so a chance of 0 never fires and 100 always does.

- **Attack special** (CD `MAIN.EXE+0x1198C`, floppy `+0x16428`): chance byte `+0x4C`, type byte `+0x4D`. It has one caller in each edition, a same-segment call (`push cs` followed by a near `call`) in the monster melee routine at CD `+0x11E67`, floppy `+0x16820`. That routine calls it after a nonzero hit test and after the damage routine, with the monster, the hit character and the damage word it passed to the damage routine.
- **Defense special** (CD `+0x11BEA`, floppy `+0x165F8`): chance byte `+0x4E`, type byte `+0x4F`. It has one caller in each edition, a far call inside the damage routine at CD `+0xB1FD`, floppy `+0xB11F`. That call is on the branch for positive damage to a monster, after the HP clip, and is skipped when the attacker word has bit `0x8000` (a monster attacker), so only a character's hit can trigger it. The arguments are the monster, the attacker, the damage routine's flags word, its skill word and the damage.
- No other far call, near call or stored far pointer to either routine was found in the whole file, overlays included.

`lol1_attack_types.py --check` re-reads the bounds, both jump tables, the first bytes of every arm, the two return arms, the single callers and the panic routine in both editions. What each arm does is below; the names of the record fields follow the [native records](unknowns/18_native_records.md#monster-definition) and ScummVM's `applyMonsterAttackSkill` and `applyMonsterDefenseSkill` (LoL:3711–3848, Script:969–972, Sprites:1297–1304), which have the same arms. The NUMBERS page lists each creature's [attack chance and attack type](NUMBERS.md#creature-definitions-by-level); among the CD rows there, types 5 and 7 do not occur.

The arms compare the damage routine's flags word with 2, 3, `0x80` and `0x84`, and with an item-type byte, but which weapons, spells or attacks pass those values was not traced here. That the panic direction faces away from the party is ScummVM's reading (`calcMonsterDirection(...) ^ 4`); the helper at CD `0x1AFA:0x10` was not read. ## Magic

**CONFIRMED** The 17 spell records agree across the two CD images and the floppy. Rows 0–9 have four MP amounts per rank plus four HP amounts; all populated rows have zero HP costs in all four columns. Native records at CD `MAIN.EXE+0x2B5E0` and floppy `MAIN.EXE+0x2CE80`; `devtools/create_kyradat/resources/lol_dos_cd.h:501–521` and `lol_dos.h:453–473`. English labels come from the original `LANDS.ENG` lookup words at CD `STARTUP.PAK+0x8B50–0x8B5F, +0x8F86` and floppy `GENERAL.PAK+0xD4F9F–0xD4FAE, +0xD53D5` (LoL:1066–1104).

**CONFIRMED** Ordinary casts require MP ≥ cost and HP > cost, then dispatch by the low byte of the spell property word. The direct effect path skips payment. CD decodes a negative caster as slot `−ID − 1`, and floppy recognizes −1 and uses slot 0. Vortex has a cost record and a null effect pointer. See the [native spell effect table](unknowns/07_native_rules.md#casting) for each rank's effects, damage inputs and the executable offsets.

Spell effects by rank are not repeated on this page. The native spell effect table already lists, from the program code of both editions, what each spell does at ranks I to IV (damage inputs, heal caps, durations and targets); the 19 November attack-type work added no new spell table and changed none of its rows.

## Monster behavior

The [native monster update](unknowns/07_native_rules.md#monster-transitions) documents the 0–16 transitions, position and speed checks, and the edition difference in spawn HP on level 12.

- **CONFIRMED** Movement steps add 32 along each applicable axis and wrap to 13 bits (CD `MAIN.EXE+0x10EC4–0x10EF3`, step words at `+0x33F0A`). Ranged scans require a clear cardinal line, facing toward the target, within four blocks (CD `+0x1242B–0x124EF`, called with 4 at `+0x12516–0x1252A`). A ranged attack uses one charge unless charges are 255, and sets its next counter to `speed stat × 8 / 256` (CD `+0x1272B–0x12755`). Melee uses forward distance at most 160 and absolute lateral distance at most 80, with matching facing and direction (CD `+0x12043–0x120DC`). Sprites:1205–1313,1381–1415,1428–1434.
- **CONFIRMED** Difficulty rows 1–3 in easy/normal/hard order are `[102,256,384]` CD or `[192,256,384]` floppy for row 1, `[256,256,192]` for row 2, and `[320,256,128]` for row 3 in both. Native CD `MAIN.EXE+0x2B85C`, floppy `+0x3251C`. **CONFIRMED** Row 1 scales a new monster's HP (property HP × row 1 / 256, raised to at least 1; CD `MAIN.EXE+0x14740–0x147B1`, floppy `+0x190E6`). Row 2 scales only the character attack-recovery interval (CD `+0xAA19–0xAA3B`, floppy `+0xA955–0xA977`); ScummVM applies row 2 to monsters instead. Row 3 scales a monster's recovery after its melee attack, `(8 × 256 / speed stat) × row 3 / 256` (CD `+0x1298C–0x129D3`, floppy `+0x17359`). Changing difficulty in the options menu rescales the live monsters of the current level. Each monster below mode 14 with a block and HP above 0 gets `HP × (row1[new] × 256 / row1[old]) / 256`, plus one if the new index is lower, and zero becomes one (CD `+0x4BF8A–0x4BFB5, +0x4C0E8–0x4C186`, floppy `+0x54F5C–0x54F67`). ScummVM instead scales by old / new when a stored level is restored. Sprites:478–483,1114–1119, `engines/kyra/gui/saveload_lol.cpp:547–561`.
